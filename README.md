# ومضة — نظام إدارة تحويلات وصرافة

FastAPI (Python، SQLAlchemy 2.0، PostgreSQL) + React/TypeScript. راجع
`PROGRESS.md` للسجل الكامل لكل مرحلة (يجب قراءته كاملاً قبل أي عمل جديد).

## توليد المستندات (§٨) — القرار المعماري: Playwright لا WeasyPrint

كل إيصال/كشف حساب/تقرير مطبوع (PDF أو PNG) يُولَّد على السيرفر عبر
**Playwright/Chromium** (`app/documents/render.py`)، لا WeasyPrint.

**لماذا؟** جُرِّب WeasyPrint أولاً (المرحلة ١٠). يحتاج مكتبات نظام تشغيل
حقيقية (GTK3/Pango/gobject) خارج أي شيء يوفّره `pip`. فشل فعلياً أثناء
البناء: النسخة المتاحة من مثبِّت GTK3 على جهاز التطوير كانت ٣٢-بت بينما
Python المشروع ٦٤-بت (خطأ `0xc1`، عدم توافق بنية) — ولا ضمان أن خادم
النشر (لينكس) سيُثبَّت عليه GTK3/Pango بسلاسة أكبر. Playwright كان مثبَّتاً
أصلاً منذ المرحلة ٥ (يُستخدَم للتحقق الآلي من كل شاشة) ولا يحتاج أي اعتماد
نظام تشغيل إضافي على أي منصة — ونتيجته مطابقة تماماً لما يظهر في المتصفح
لأنه نفس محرك العرض بالضبط، لا محاكاة CSS منفصلة.

**الطبقة الموحَّدة**: قوالب Jinja2 (`app/documents/templates/`) → HTML →
`page.pdf()` أو `page.screenshot()` (`app/documents/render.py`). نفس
القالب يُستخدَم لكل مقاسات المخرَج (A4 · ٨٠مم حراري · PNG) — الفرق بينها
متغيّر `doc_size` داخل نفس القالب (`@page size`/عرض الحاوية)، لا قوالب
منفصلة.

**متصفح واحد لكل عمر العملية** — يُشغَّل مرة عند إقلاع FastAPI
(`main.py` lifespan) ويُعاد استخدامه لكل طلبات PDF/PNG، لا تشغيل/إغلاق
متصفح لكل مستند (بطيء جداً على السيرفر). Playwright غير متزامن أصلاً؛
بقية المشروع متزامن بالكامل — الجسر بينهما خيط خلفية واحد مخصَّص يشغّل
حلقة asyncio يملك المتصفح طوال عمر التطبيق (تفصيل كامل في
`app/documents/render.py`).

**⚠ فخ حقيقي وقع أثناء البناء نفسه، صحَّحه اختبار حي لا افتراض**:
lifespan التطبيق (`doc_render.start()`/`stop()`) يُطلَق مرة واحدة على
خادم uvicorn حقيقي — لكنه يُطلَق **مرة لكل ملف اختبار** في `pytest` (كل
`with TestClient(app) as c:` جديد يشغّل دورة lifespan كاملة). استدعاء
`stop()` من داخل الـlifespan كان يُغلق المتصفح الحقيقي بعد كل ملف اختبار
فيُعاد تشغيله من الصفر في التالي — رفع وقت مجموعة `pytest` الكاملة من
**~دقيقتين إلى أكثر من ٣ ساعات** (اكتُشف بتشغيل حقيقي كامل، ليس قياساً
تقديرياً). أُصلح بحذف استدعاء `stop()` من الـlifespan: الخيط خلفية
(`daemon=True`) وعملية Chromium الفرعية تُنهيان تلقائياً مع خروج عملية
Python نفسها على أي حال — لا حاجة فعلية لإغلاق صريح في كلا السياقين
(خادم حقيقي أو جلسة اختبار).

**الخط**: IBM Plex Sans Arabic مضمَّن محلياً (`app/static/fonts/*.woff2`،
Base64 داخل كل مستند مباشرة — لا CDN، لا اعتماد على خطوط النظام وقت
النشر). مصدره حزمة npm الرسمية `@ibm/plex-sans-arabic` (ترخيص OFL-1.1).

## التشغيل محلياً

```
pip install -r requirements.txt
playwright install chromium   # مرة واحدة — محرك توليد المستندات
python -m app.cli seed
uvicorn app.main:app          # بلا --reload عمداً — انظر أدناه
```

راجع `.env.example` لمتغيّرات البيئة المطلوبة.

**بلا `--reload` إطلاقاً** (قرار المرحلة ٧، ساري): مُراقِب `--reload` يعيد
تشغيل العملية بمفسّر Python مختلف عن المقصود فتنكسر البيئة بصمت. أعِد
التشغيل يدوياً بعد أي تعديل خلفي، وتحقّق دائماً بـ
`curl http://127.0.0.1:<port>/openapi.json` قبل أي اختبار حيّ.

## النسخ الاحتياطي والجدولة (§٩)

### الوجهة الخارجية — مجلد مُزامَن سحابياً

`BACKUP_OFFSITE_DIR` (`.env`) يجب أن يكون **مجلداً تُزامنه فعلياً أداة
سحابية** على السيرفر (Google Drive / OneDrive أو مكافئ): النسخة المُشفَّرة
تُكتَب في المجلد، وأداة المزامنة ترفعها خارج السيرفر. لا SFTP ولا مزوّد
إضافي (قرار المالك، ٢٠٢٦-٠٩).

- الأمر لا يُنشئ المجلد. إن كان غائباً أو غير قابل للكتابة، `backup` يطبع
  **تحذيراً صريحاً** ويُبقي النسخة محلية فقط — لا فشل صامت ولا افتراض رفع
  لم يحدث.
- **الاعتماد على أداة المزامنة يعني أننا لا نملك تأكيداً لحظياً أن الملف
  وصل السحابة.** لذلك تحقُّق يدوي **شهري** إلزامي: افتح واجهة التخزين
  السحابي وتأكّد أن أحدث ملف `wamda-*.dump.enc` ظاهر هناك بحجم مطابق
  وتاريخ اليوم/الأمس. سجّل تاريخ كل تحقُّق.
- `check-backup-freshness` المجدول يفحص المجلد المحلي فقط (عمر أحدث ملف
  فيه). إن لم تصل نسخة جديدة خلال **٤٨ ساعة** ⇒ تنبيه `critical` في لوحة
  التحكم بجانب تنبيه فحص السلامة مباشرةً — **نسخة لم تُرفع أخطر من نسخة لم
  تُنشأ** (قد تُظَنّ آمنة خطأً). الفحص لا يرى الطرف السحابي؛ التحقُّق
  الشهري اليدوي هو ما يسدّ هذه الفجوة.

### المهام المجدولة (cron / systemd timer على خادم النشر)

| الأمر | التكرار المقترَح | الأثر عند الفشل |
|---|---|---|
| `python -m app.cli backup` | يومياً | يطبع تحذيراً، exit 1 لا يحدث — راقِب المخرَج |
| `python -m app.cli daily-integrity-check` | يومياً | exit 1 + تنبيه critical في لوحة التحكم |
| `python -m app.cli check-backup-freshness` | يومياً (بعد `backup`) | exit 1 + تنبيه critical في لوحة التحكم |
| `python -m app.cli restore-test <أحدث نسخة>` | أسبوعياً | يفشل إن لم تُستعَد النسخة أو اختلّت أرصدتها |

جدولة النشر الفعلية (وحدات systemd / سطور crontab) تُكتب في المرحلة ١٥.

### إعادة تعيين كلمة مرور المدير من السيرفر

`python -m app.cli reset-admin-password` (تفاعلي، `getpass`) — طوارئ
استعادة وصول فقط، لا يُنشئ حساباً جديداً.

## التقسية الأمنية (§٩ — المرحلة ١٢)

### رؤوس الأمان

`app/main.py` يضيف على **كل** رد: `Content-Security-Policy` صارمة
(`script-src 'self'` — لا سكربت سطري ولا CDN؛ الخط مُستضاف محلياً)،
`Permissions-Policy` تُعطِّل كل ميزة متصفح غير مستخدَمة، `X-Frame-Options:
DENY` (+ `frame-ancestors 'none'`)، `X-Content-Type-Options`،
`Referrer-Policy`، و`Cache-Control: no-store` على كل رد غير الأصول الثابتة.

### إعداد النشر الإلزامي

- **`APP_ENV=production`** في `.env` على الخادم: يُفعّل `Strict-Transport-Security`
  (HSTS، سنة + النطاقات الفرعية) ويُعطّل `/docs` و`/redoc` (تبقى
  `/openapi.json` للتحقق الآلي).
- **uvicorn بـ`--no-server-header --proxy-headers --forwarded-allow-ips=127.0.0.1`**:
  الأول يمنع كشف نسخة uvicorn في `Server`؛ الأخيران يجعلان `request.client`
  يعكس عنوان العميل الحقيقي خلف nginx (يلزم لتحديد المعدل — بلا ذلك يصبح
  الحدّ عامّاً لا لكل عميل). nginx يجب أن يمرّر `X-Forwarded-For`.
- **nginx `server_tokens off;`**: مكافئ على مستوى الوكيل العكسي. وحدة
  systemd وإعداد nginx الفعليان في المرحلة ١٥.

```
APP_ENV=production uvicorn app.main:app --no-server-header \
  --proxy-headers --forwarded-allow-ips=127.0.0.1 --host 127.0.0.1 --port 8000
```

### تحديد معدل مسارات الدخول

`POST /auth/login` و`POST /portal/login` فقط (لا يمسّ أي طلب قراءة) —
نافذة منزلقة لكل عنوان IP، طبقة فوق قفل الحساب الفردي (٥ محاولات/١٥ دقيقة).
حدّان منفصلان: الموظف `LOGIN_RATE_LIMIT_MAX=10` (عنوان ثابت)، العميل
`PORTAL_LOGIN_RATE_LIMIT_MAX=30` (هاتف بشبكة متغيّرة). عدّاد في الذاكرة —
يكفي لعامل uvicorn واحد؛ نشر متعدد العمّال يحتاج مخزناً مشتركاً (غير مطلوب
في نشر AL SAHEM المخطَّط).

**العنوان خلف nginx**: في `APP_ENV=production` يُقرأ من `X-Real-IP` (يُفضَّل)
وإلا آخر مُدخَل في `X-Forwarded-For` (النظير المباشر كما ألحقه nginx —
لا يُخدَع بمُدخَلات يسارية يزوّرها العميل). خارج الإنتاج تُتجاهَل كل
ترويسات الوكيل ويُستخدَم عنوان الاتصال المباشر. إعداد nginx المطلوب:

```nginx
proxy_set_header X-Real-IP        $remote_addr;
proxy_set_header X-Forwarded-For  $proxy_add_x_forwarded_for;
```

### تعطيل مستخدم أو تغيير دوره

`PATCH /users/{id}` (مدير فقط، مُسجَّل في `audit_log`). التعطيل يُبطل كل
جلسات المستخدم فوراً؛ تغيير الدور يسري من الطلب التالي (`get_current_user`
يقرأ `is_active`/`role` طازجَين كل طلب). المدير لا يعطّل نفسه ولا يخفض دوره.
