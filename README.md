# ومضة — نظام إدارة تحويلات وصرافة

FastAPI (Python، SQLAlchemy 2.0، PostgreSQL) + React/TypeScript. راجع
`PROGRESS.md` للسجل الكامل لكل مرحلة (يجب قراءته كاملاً قبل أي عمل جديد).

## توليد المستندات (§٨) — القرار المعماري: Playwright لا WeasyPrint

كل إيصال/كشف حساب/تقرير مطبوع (PDF أو PNG) يُولَّد على السيرفر عبر
**Playwright/Chromium** (`app/documents/render.py`)، لا WeasyPrint.

**لماذا؟** جُرِّب WeasyPrint أولاً (المرحلة ١٠). يحتاج مكتبات نظام تشغيل
حقيقية (GTK3/Pango/gobject) خارج أي شيء يوفّره `pip`. فشل فعلياً أثناء
البناء: النسخة المتاحة من مثبِّت GTK3 على جهاز التطوير كانت ٣٢-بت بينما
Python المشروع ٦٤-بت (خطأ `0xc1`، عدم توافق بنية) — ولا ضمان أن خادم
النشر (لينكس) سيُثبَّت عليه GTK3/Pango بسلاسة أكبر. Playwright كان مثبَّتاً
أصلاً منذ المرحلة ٥ (يُستخدَم للتحقق الآلي من كل شاشة) ولا يحتاج أي اعتماد
نظام تشغيل إضافي على أي منصة — ونتيجته مطابقة تماماً لما يظهر في المتصفح
لأنه نفس محرك العرض بالضبط، لا محاكاة CSS منفصلة.

**الطبقة الموحَّدة**: قوالب Jinja2 (`app/documents/templates/`) → HTML →
`page.pdf()` أو `page.screenshot()` (`app/documents/render.py`). نفس
القالب يُستخدَم لكل مقاسات المخرَج (A4 · ٨٠مم حراري · PNG) — الفرق بينها
متغيّر `doc_size` داخل نفس القالب (`@page size`/عرض الحاوية)، لا قوالب
منفصلة.

**متصفح واحد لكل عمر العملية** — يُشغَّل مرة عند إقلاع FastAPI
(`main.py` lifespan) ويُعاد استخدامه لكل طلبات PDF/PNG، لا تشغيل/إغلاق
متصفح لكل مستند (بطيء جداً على السيرفر). Playwright غير متزامن أصلاً؛
بقية المشروع متزامن بالكامل — الجسر بينهما خيط خلفية واحد مخصَّص يشغّل
حلقة asyncio يملك المتصفح طوال عمر التطبيق (تفصيل كامل في
`app/documents/render.py`).

**⚠ فخ حقيقي وقع أثناء البناء نفسه، صحَّحه اختبار حي لا افتراض**:
lifespan التطبيق (`doc_render.start()`/`stop()`) يُطلَق مرة واحدة على
خادم uvicorn حقيقي — لكنه يُطلَق **مرة لكل ملف اختبار** في `pytest` (كل
`with TestClient(app) as c:` جديد يشغّل دورة lifespan كاملة). استدعاء
`stop()` من داخل الـlifespan كان يُغلق المتصفح الحقيقي بعد كل ملف اختبار
فيُعاد تشغيله من الصفر في التالي — رفع وقت مجموعة `pytest` الكاملة من
**~دقيقتين إلى أكثر من ٣ ساعات** (اكتُشف بتشغيل حقيقي كامل، ليس قياساً
تقديرياً). أُصلح بحذف استدعاء `stop()` من الـlifespan: الخيط خلفية
(`daemon=True`) وعملية Chromium الفرعية تُنهيان تلقائياً مع خروج عملية
Python نفسها على أي حال — لا حاجة فعلية لإغلاق صريح في كلا السياقين
(خادم حقيقي أو جلسة اختبار).

**الخط**: IBM Plex Sans Arabic مضمَّن محلياً (`app/static/fonts/*.woff2`،
Base64 داخل كل مستند مباشرة — لا CDN، لا اعتماد على خطوط النظام وقت
النشر). مصدره حزمة npm الرسمية `@ibm/plex-sans-arabic` (ترخيص OFL-1.1).

## التشغيل محلياً

```
pip install -r requirements.txt
playwright install chromium   # مرة واحدة — محرك توليد المستندات
python -m app.cli seed
uvicorn app.main:app --reload
```

راجع `.env.example` لمتغيّرات البيئة المطلوبة.
